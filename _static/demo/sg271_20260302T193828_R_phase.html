PHASE says what the glider was doing at each data point, in the OG1 phase vocabulary. How phase should be assigned is under discussion in the OceanGliders community.

We use the OG1 phase translation table to determine how to assign phase for Seagliders. 6 (propelled) and 7 (transition) are never assigned to a Seaglider.

(3) Pitch and dP/dt

Dive 2, 3: pitch against the rate of pressure change, colored by PHASE. Descent sits at negative pitch and positive dP/dt (i.e., increasing pressure), ascent at positive pitch and negative dP/dt; inflection lies between them. Descent points at steep negative pitch and dP/dt near zero are the glider bleeding at the surface before the flare; ascent points at positive pitch with dP/dt still positive are the glider still sinking after the apogee ends. Pitch is interpolated in time onto the pressure data points.

(4) Algorithm

The code: PHASE is assigned by assign() in seagliderOG1/_phase.py, called through the public wrapper seagliderOG1.tools.add_phase(); PROFILE_NUMBER, PROFILE_DIRECTION and SEGMENT_NUMBER follow from it in tools.add_profiles().

The file's phase_calculation_method:

From the glider's state table (gc_state_state) on dives 1-3. Data points at GPS fix times are surfacing; no command (log_D_FLARE, log_D_TGT, log_D_SURF, log_LOITER_*) is used.

The algorithm as the code runs it, per dive. Step 2 overrides step 1; step 3 fills what is left.

for each dive:
    PHASE = 0 (unknown) on every data point

    # step 1: from the first signal the file has
    if the dive has a state table (gc_state_state):
        sort states by time (same-second states keep file order)
        each begin state of a transition the OG1 phase translation table lists
        (Seaglider column) sets the PHASE it specifies, from its time until the
        next listed begin state:
            0 begin dive    (-> 1 end dive)             2 descent
            2 begin climb   (-> 3 end climb)            1 ascent
            4 begin apogee  (-> 5 end apogee)           5 inflection
            6 begin loiter  (-> 7 end loiter)           4 parking
            10 begin subsurface finish (-> 11 end)      5 inflection
            14 begin surface (-> 15 end surface)        3 surfacing
          not listed in the OG1 table, so ignored (the phase before
          them holds):
            8 begin surface coast -> 9 end surface coast
            12 begin recovery     -> 13 end recovery
          a code with no name -> WARNING, ignored
        the last listed transition runs to the end of the dive file
        data points before the first listed begin state take the phase of the
          first listed end state (a file opens with 15 end surface -> 3 surfacing)
    elif the dive has G&C events (gc_vbd_ctl, gc_end_secs):
        apogee = the event with VBD at zero after an event with VBD bled (negative);
                 if several, the one nearest the deepest sample
        data points before the apogee event -> 2 descent
        data points in the apogee event     -> 5 inflection
        data points after it                -> 1 ascent
    else:
        data points up to the (last) pressure maximum -> 2 descent
        data points after it                          -> 1 ascent

    # step 2: GPS fixes
    GPS fix data points (TIME_GPS finite) -> 3 surfacing
      (the CTD does not sample at the surface: these are the fix data points only)

    # step 3 (state table only): data points still 0 take the phase of the
    # data point before them

PHASE_QC = 0 (no QC performed) on every data point
No transition (7): the OG1 table gives Seaglider none.

(5) Seaglider state table

Every state the Seaglider basestation numbers in gc_state_state, in begin/end pairs. Each begin state of a pair sets the PHASE the OG1 phase translation table specifies the transition, held until the next listed pair begins; a pair the table does not list is ignored, so the phase before it holds. Count: how many times the begin state appears in this file. Ended with: the end-of-phase codes (gc_state_eop_code) the end state carried. Names and numbers: the basestation's own list.
