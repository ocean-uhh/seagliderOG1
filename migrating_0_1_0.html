Migrating to 0.1.0

0.1.0 is a breaking release: the public API was reshaped to the OceanGliders family convention (a clean break, no deprecation shims), and the output format changed. This page is the “what you need to change” reference; the Changelog lists the changes tersely.

Output-format changes

  • Variable dtypes. QC flags are int8 (were float32/int64) and use 6 for unsampled with no _FillValue; PHASE is int8; PROFILE_NUMBER, DIVE_NUMBER and VBD_MIN_CNTS are int16; DEPTH and DEPTH_Z are float32; LATITUDE/LONGITUDE stay float64. A reader that assumes the old dtypes, or tests np.isnan on a QC flag, must adapt; CF-decoding readers are unaffected.

  • Time units. seconds since 1970-01-01T00:00:00Z / gregorian (was the non-conformant seconds since 1970-01-01 00:00:00 / standard). The instant is unchanged; a parser that string-matched the old units must adapt.

  • TEMP units are degree_Celsius (CF spelling) rather than Celsius; values unchanged.

  • featureType / Conventions. featureType is trajectory (was trajectoryProfile); Conventions is CF-1.10, ACDD-1.3, OG-1.0 (was CF-1.10,OG-1.0).

  • No placeholders. A missing mandatory global is no longer written as null / null@null.com; a config that relied on the fabricated email must set a real contributor_email. convert.to_og1 raises MetadataError on a missing mandatory global.

  • Per-dive-varying scalars (e.g. the flight-model constants C_VBD, HD_A/HD_B/ HD_C) are written as a JSON-string scalar variable ({"dives": [...], "values": [...]}, tagged serialization: json) instead of broadcast onto N_MEASUREMENTS. Decode the JSON to read them.

  • Conversion provenance in the output. Every variable carries original_name (its basestation name; equal to the OG1 name when it passed through unrenamed), and merged variables also carry original_dimension. New globals record the conversion: conversion_dimensions (each basestation dimension’s fate and the variables it carried), conversion_derived_variables (the converter-created variables mapped to the basestation variables they consumed), conversion_dropped_variables, conversion_removed_variables, conversion_input_variable_count and conversion_attribute_sources. convert.conversion_ledger(ds) reads them back and seagliderOG1 inspect --conversion prints them (-o writes an HTML page). The attribute is original_name — code that read the development-only original_variable_name must use original_name.

  • history is a single conversion provenance line; the basestation comment is no longer renamed to history. A reader that parsed the old per-dive processing log out of history must adapt.

Metadata now comes from the mission config

Platform, contributor, institution and deployment metadata are supplied in mission.yaml (see mission.yaml reference), not defaulted inside the package:

  • A missing PLATFORM_SERIAL_NUMBER (no file platform_id, none in the config) raises instead of defaulting to sg000; other platform fields are written "UNK" with a warning rather than 0000000 or a hard-coded model.

  • convert.to_og1 takes contributors=, institutions=, platform=, deployment=, global_attributes= as lists/dicts from the config. A missing contributor role is no longer defaulted to PI; an unrecognised institution is no longer stamped with a default EDMO code.
