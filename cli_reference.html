CLI reference

The seagliderOG1 command converts Seaglider basestation files to OG1 with one subcommand per verb. The typical workflow is init → validate → process; inspect and list are read-only helpers.

$ seagliderOG1 init --from /data/005/20080606 -o sg005.yaml
$ seagliderOG1 validate sg005.yaml
$ seagliderOG1 process  sg005.yaml

The same entry point is available as a module:

$ python -m seagliderOG1.cli --help

See mission.yaml reference for the configuration file the verbs read and write.

Data mode

process --mode (and the mode key in mission.yaml) sets the OG1 data mode, which determines the data-mode suffix of the output id: realtime gives the suffix R and delayed gives delayed (vocabularies.MODE_SUFFIX).

Verbs

Convert Seaglider basestation files to OG1 format.

usage: seagliderOG1 [-h] [--version] <command> ...

Positional Arguments

<command>

Possible choices: init, validate, process, inspect, list

Named Arguments

--version

show program’s version number and exit

Sub-commands

init

write a commented mission.yaml template

seagliderOG1 init [-h] [--from DIR] [-o OUTPUT] [--force]
Named Arguments
--from

basestation directory to read the platform block from

-o, --output

output path (default: mission.yaml)

Default: 'mission.yaml'

--force

overwrite an existing file

Default: False

validate

check a mission.yaml for errors

seagliderOG1 validate [-h] [--strict] config
Positional Arguments
config

path to mission.yaml

Named Arguments
--strict

also require every dive in the range to be present (no gaps)

Default: False

process

convert basestation missions to OG1 files

seagliderOG1 process [-h] [--source DIR_OR_ROOT] [--all | --mission GLOB]
                     [-o DIR] [--mode {realtime,delayed}] [--dives FIRST LAST]
                     [--repair] [--force | --skip-existing] [-n]
                     config
Positional Arguments
config

path to mission.yaml

Named Arguments
--source

override the config source (a mission dir or a root of SN/DATE dirs)

--all

convert every SN/DATE mission under a root

Default: False

--mission

select missions by SN/DATE glob, e.g. ‘103/*’

-o, --output-dir

override the config output_dir

--mode

Possible choices: realtime, delayed

override the config data mode

--dives

dive range to convert (overrides the config dives)

--repair

repair basestation time metadata before loading (writes the source tree)

Default: False

--force

overwrite an existing output file

Default: False

--skip-existing

skip a mission whose output file already exists

Default: False

-n, --dry-run

print what would be written; write nothing

Default: False

inspect

Show the inventory of one basestation or OG1 netCDF file. Writes an HTML inventory page with the seagliderOG1[report] extra; otherwise prints a text table.

seagliderOG1 inspect [-h] [--attrs | --variables | --by-dimension DIM]
                     [-o HTML] [--title TEXT]
                     file
Positional Arguments
file

path to a basestation or OG1 netCDF file

Named Arguments
--attrs

show global attributes

Default: False

--variables

show variables (the default)

Default: False

--by-dimension

show only variables on dimension DIM

-o, --output

write the HTML inventory page to this path

--title

title for the inventory page

Examples:

seagliderOG1 inspect sg005_20080606_delayed.nc variables as a table seagliderOG1 inspect sg005_20080606_delayed.nc –attrs global attributes seagliderOG1 inspect p0050001.nc –by-dimension sg_data_point

list

print a registry: roles, institutions, or missions

seagliderOG1 list [-h] {roles,institutions,missions} [path]
Positional Arguments
registry

Possible choices: roles, institutions, missions

which registry to print

path

root or mission directory (required for ‘missions’)

typical workflow:

seagliderOG1 init –from /data/005/20080606 -o sg005.yaml template from the first file seagliderOG1 validate sg005.yaml config, source, dive range seagliderOG1 process sg005.yaml -> <output_dir>/<OG1 id>.nc

Exit status

  • 0 — success.

  • 1 — a handled error (a missing file, an invalid configuration, a conversion that wrote nothing).

  • 2 — a usage error (argparse: an unknown flag or a missing argument).
